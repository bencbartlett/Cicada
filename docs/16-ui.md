# UI specification

Structure and interaction contracts for the app — the level an agent
needs to build stage 5 without inventing layout, plus the GH-migrant
conventions worth locking. **Pixel-level aesthetics are deliberately
not specified**; they iterate in code behind these contracts. This doc
consolidates the UI decisions scattered through docs 02, 04, 09, 10,
12, and 13.

## Application layout

One window, docked (doc 04). Regions:

```
┌─────────────────────────────────────────────────────────────┐
│ Top bar: project · branch/git status · lease/role chip      │
│          (writer / read-only observer · take lease) · solve │
│          state + ETA + Esc                                  │
├─────────────────────────────────────────────────────────────┤
│ Ribbon: category tabs — Params · Maths · Sets · Vector ·    │
│         Curve · Surface · Mesh · Intersect · Transform ·    │
│         Display  (GH-style; drag or click to place)         │
├───────────────────────────────────┬─────────────────────────┤
│  Canvas          ⇅ resizable      │  Inspector              │
│  ──────────────────────────       │  (node / wire /         │
│  Viewport                         │   selection)            │
├───────────────────────────────────┴─────────────────────────┤
│ Transport bar (only with time params): ▶/❚❚ · ⏮ · frame /  │
│          frames · scrubber · playhead s · speed · drives …  │
├─────────────────────────────────────────────────────────────┤
│ Status bar: diagnostics count · cache stats · generation    │
└─────────────────────────────────────────────────────────────┘
```

- **The ribbon is the GH tab bar**: category tabs populated from the
  JSON catalog (the docs/08 categories verbatim); drag a node onto
  the canvas or click to place at cursor. Project script nodes appear
  under their declared category (or a Project tab). Collapsible to
  tab names only — search-to-place remains the power path, the
  ribbon is the browsable one.

- **The URL is the route, and the File menu changes it** (shipped
  2026-08-24, v0.1 wave 4 O2 — docs/17 finding U3). `?token=` alone IS
  the **landing picker**: the served root's file list, one directory at
  a time over `GET /api/files` (never `/api/project`, whose walk over a
  home root takes seconds and lists what the picker must not show —
  docs/17 O1), with breadcrumbs (the root's name, then each segment —
  click to climb out), directories first and then the `.cic` files, and
  the keyboard: arrows move, Enter opens (a directory descends, a
  pipeline opens), Backspace goes up, Home/End jump, a double-click is
  Enter; above it, **Recent** — the last ten pipelines this origin
  opened, most recent first (`localStorage`, remembered on the session's
  `hello`, so a file the server refused never becomes recent). A
  pipeline in the URL (`&pipeline=`) is the docked app on that
  pipeline's session. The top bar's **File** menu, left of the project
  name: **Open…** (the same browser in a dialog, starting in the open
  pipeline's directory; Esc or a click outside closes), **Recent** (the
  same ten; the open one marked), **Close** (back to the picker — every
  edit is already on disk, so closing asks nothing). Every choice is one
  `history.pushState` of the new `?token=…&pipeline=…` plus a reconnect:
  the socket to the previous pipeline's session closes (the server's
  session lives on for whoever else has it; the last client leaving
  pauses its transport), the store's pipeline-bound state is cleared —
  mirror, read caches, transport, selection, the viewport's ledger — and
  the new session's `hello` + `snapshot` + restream hydrate it (the one
  hydration path, docs/13); settings, notices and the catalog survive
  (the join's snapshot re-reads the catalog for the new pipeline's
  script nodes). So the browser's **Back** returns to the previous file
  (or to the picker, and Back from the picker reopens the file), Forward
  goes on again, and the file already open is never reopened by a
  no-op route. The tab's title is the pipeline's name. **A new file is a
  new canvas**: the canvas remounts on a switch and frames the new graph
  itself, never showing it at the previous file's zoom and offset (the
  viewport stays — its camera is the user's). **A pipeline the server no
  longer has** — a Recent entry for a renamed or deleted file, a stale
  URL — never leaves the tab on an empty canvas: the join's typed
  refusal (docs/13 §Projects, pipelines, sessions — kind `pipeline`) is
  terminal, so no reconnect is attempted; the server's reason is shown
  as a notice on the picker the tab returns to, a `not_found` file is
  dropped from Recent with a second notice saying so, and the dead URL
  is REPLACED in the history, so Back does not ask for it again.
  `web/e2e/files.spec.ts` is the evidence.
- **Canvas / viewport split** is resizable with presets (canvas-focus,
  50/50, viewport-focus) and a swap. Both always live; there is no
  modal switching.
- **Text panel** (toggleable, right side or bottom): a **read-only
  view of the `.cic` file** (v1), scrolled and highlighted in sync
  with canvas selection — select a node, see its binding. This
  reinforces text-as-truth, teaches the dialect passively, and is
  where agent diffs are reviewed. Editing stays canvas-only (locked
  decision); the panel gains an edit mode only if evidence demands.
- **Params panel** lives in the inspector region as a tab:
  auto-generated from param nodes (doc 02), grouped by canvas groups.
- **Transport bar** (doc 13 §Animation transport; shipped 2026-08-20,
  v0.1 item 4). Docked above the status bar — the sketch once put it
  in the top bar; it moved down with the scrubber, which wants the
  width — and present only while the pipeline has a time param the
  transport drives (`TransportView.driven` non-empty; `cycle` / `clock`
  that lowered — a red one drives nothing and shows no bar). Left to
  right: play / pause (`Space`), reset (pause + rewind to frame 0 — the
  headless values), the frame counter `frame / frames`, a scrubber over
  the primary loop (every change is a `transport_seek`: a scrub stream
  is a stream of latest-wins generations, each painting the frame it
  names; the arrows step one frame), the playhead in seconds, the speed
  menu (`0.25× · 0.5× · 1× · 2× · 4×`, plus the server's speed when it is
  none of them — the menu shows what IS), and `drives spin.frame`.
  Nothing in the bar flips locally: each control is an intent and the
  `transport` broadcast that answers changes the view — the button reads
  `play` until the server says `playing`; between broadcasts the counter
  and the thumb extrapolate `t_ms + elapsed × speed` on a 30 Hz display
  tick. A refused control (a seek beyond the loop, a speed that is not
  finite and positive or is above the server's 64× bound, an observer's)
  is answered by the error toast alone — nothing is broadcast, the view
  stands. A scrub thumb shows the sought frame until the LATEST seek is
  answered — the broadcast naming its frame, or the error of a refused
  one — and then hands back to whatever view stands (at the release if
  the pointer is still down; a foreign view landing after the answer —
  a reload, a control by the client that took the lease — is what the
  release shows: a held frame never outlives its answer). The
  bar itself offers neither refusal, a script on the socket can. Controls
  are writer-only (the lease arbitrates shared state);
  an observer sees the same bar, live, with the controls disabled and
  the reason on hover. **Transport-driven ports** (`cycle.frame`,
  `clock.t` — the catalog's `transport_driven`; until the catalog has
  arrived, the snapshot's own `driven` set names them, so a driven port
  never paints as an ordinary input for the catalog fetch's latency) are hidden as ports
  wherever a wire or an edit could reach them: on the node the row keeps
  its place but has no connectable handle and no literal editor and shows
  a `▶ transport` chip (lit while the port is in the driven set); in the
  inspector the port leaves `inputs` for a `transport` section that
  shows the frame (or seconds) it is fed, live — the frame of THAT
  port's OWN loop (a second `cycle` loops inside the primary at its own
  rate: `TransportView.driven[i].loop` carries each port's frames /
  period, and the row quantizes on it, never on the primary loop's).
  Whether it is a wire or edit target is the SERVER's rule, not the
  canvas's: the probe answers `blocked`, and `connect`, `set_param` and
  `param_preview` into it refuse with the same reason, kind `refused`
  (the lowering fills the port from the playhead whatever the text says
  — hiding the editor is the UI's courtesy, the refusal is the rule). A kwarg or wire a human
  wrote for it by hand stays in the text as the headless value / source —
  a wire keeps a target handle so the edge is drawn (never silently
  dropped) and is named `← n.out (headless)` and removable; only never
  offered or edited here.
- **Git panel** (doc 10) as an inspector tab: status, node-level
  visual diff, commit, per-node history. *Shipped 2026-08-20 (v0.1 item
  2, slice 1): the **Git tab** shows where the project stands (branch or
  `detached @short`, HEAD, upstream ahead/behind, `index.lock`, an
  unfinished merge/rebase/cherry-pick/revert), **this pipeline's nodes
  vs HEAD** grouped `added` / `modified` / `renamed` (click → select the
  node on the canvas; `removed` bindings listed with their HEAD line),
  the **files to commit** (the scope: the `.cic`, its sidecar,
  `scripts/*.py` beside it — with their git status), a commit form
  (message verbatim; `Ctrl+Enter` commits; the Commit button's tooltip
  says why it is disabled: nothing to commit, blank message, not the
  writer, locked, ignored pipeline, operation in progress), and
  **Revert to HEAD** behind an inline confirm step that says what it
  discards (every uncommitted edit in the listed files — exactly the
  files the request then names, the Playwright spec reads the request
  body; the undo history too; files without a HEAD version are named
  as left alone — which those are is the server's word per file, the
  status's `in_head`, never inferred from the file's status: an
  index-added file deleted from disk reads `deleted` and has no HEAD
  version). Measured (Playwright, debug build): Revert click → the
  reloaded text in the store 69–81 ms across runs. The **top bar's git chip** shows the branch (or `detached
  @short` / `no repo` / `git not found`) with the scope's dirty-file
  count (`clean` / `N dirty`; none for a `.gitignore`d pipeline, which
  wears `ignored` instead — git lists nothing for it) and the
  glance-worthy notes (`↑1 ↓2`, `locked`, `merge in progress`, `no
  commits yet`, `ignored`); click → the Git tab. A **read-only observer sees the
  status and none of the controls**. The status is a read of `GET
  /api/git/status` (docs/13) on connect, ≤1 s after every delta or
  barrier snapshot (one read per burst; a sidecar-only edit counts —
  the sidecar is in the scope), and on window focus — never on a timer
  while idle. Between a write's delta and that re-read the cached
  answer is marked **stale** (the moment the delta lands): the chip
  dims its count (tooltip: "an edit landed since — re-reading"), an
  empty scope reads "re-reading git status after the last edit…"
  instead of "nothing to commit — the scope matches HEAD", and Commit /
  Revert wait for the answer — the previous tree's verdict is never
  shown as current over an edit that is already on disk (an answer
  overtaken by a write mid-flight clears nothing; the follow-up read
  does). An ignored pipeline's empty scope is git's refusal, not a
  clean tree: the tab shows the ignored warning and never "nothing to
  commit" beside it. Not yet: other refs, the visual graph-diff overlay,
  per-node history (they follow once the markers have had weeks of
  use).*
- **No save button.** Every op persists to the file immediately
  (docs 10/13); `Ctrl+S` opens the commit dialog — the git-first
  reflex, repurposed honestly. *Shipped 2026-08-20: the dialog is the
  same commit form over the branch and the files it would stage;
  `Ctrl+Enter` commits, `Esc` or a click outside closes; it opens for
  everyone and, when this client cannot commit (observer, no repo, no
  git, locked, an operation in progress), says why instead of showing a
  disabled form — the reflex gets an answer, and the browser's own save
  dialog never opens. Success toasts the short hash and the summary;
  every refusal toasts one readable sentence per typed kind.*

## Canvas conventions

- **Nodes**: rectangular, grid-sized (doc 10 units), inputs on the
  left, outputs on the right, labels visible at sufficient zoom. The
  node face shows its **icon** (GH-style — see Icons below) with the
  **function name in small text above it**; together these are what
  make a graph parseable at a glance. State is worn as badges:
  progress ring / bar while running (doc 12), red with count for
  errors, amber for warnings, eye for preview-on, clock chip showing
  last compute time, buffer bar under sliders with scrub caching
  (doc 12), and — since 2026-08-20 — a **git change badge** on the
  header when the binding's line differs from HEAD (`+` added, `~`
  modified, `→` renamed, on the theme's semantic tokens; the tooltip
  says which and, for a rename, the HEAD name; removed bindings have no
  node to badge and live in the Git tab). At the **far zoom tier**,
  where header badges hide, the marker survives on the node box itself
  — a stripe down the left edge in the kind's token and the kind's tint
  over the face — so a pipeline zoomed out to a thumbnail (the wall)
  still shows what differs from HEAD.
- **Ports**: colored by kind family (one hue per kind, stable
  everywhere — wires, badges, inspector); required ports filled,
  optionals hollow; refinement-expecting ports ringed. Lift badges
  (`map ×n`, zip bracket) per doc 09.
- **Typed literals on unconnected inputs** (wave 4 B3, finding U9 —
  "no way to type `construct_domain`'s `end = 40.0` on a placed node",
  2026-08-24): every input port that is not wired and whose type takes
  a literal — `Number`, `Integer`, `Text`, `Boolean` and their `?`
  forms, never a list, never a transport-driven port (its row shows the
  transport) — wears its value as a **chip** on the node row: the
  kwarg's literal as the text spells it; else the catalog default
  greyed and dashed, spelled as the dialect would write it (`True`, not
  the macro's `true` — the server parses its own rendering into
  `InputView.default_value`); else an empty dashed slot (`…`) for a
  required port nobody typed into yet. **Double-click** the chip (a
  single click selects the node) and an input takes its place —
  number / text fields, a checkbox for a Boolean; **Enter** or leaving
  the field commits ONE `set_param {node, port, value}` spelled by the
  one literal rule (`paramValueText`: `40` on a Number port → `40.0`,
  a bare integer on an Integer port, `True`/`False`, JSON-quoted
  text); the server rewrites the kwarg's literal — inside its `each(…)`
  when the text lifts it, so the lift stays — or ADDS the kwarg at its
  spec-order position when the call lacks it (docs/10 round-trip
  table). **Esc** cancels. The typed editor streams no preview: Enter
  is the one write, so a cancelled edit leaves nothing behind; a value
  EQUAL to what the chip showed writes nothing (by value, not only by
  spelling: Enter over a Number port's `start=0` writes no `0.0`); an
  unspellable one is a warning notice, never a write — `2.5` on an
  Integer port, and `3,5`, `1/2`, `abc`, `0x10` anywhere, because the
  number editor is a plain text field that hands every keystroke to the
  one rule (a browser `type="number"` input sanitises first — `3,5`
  would have been written as `35.0`, the B3 review's finding) and the
  rule accepts exactly the dialect's number spellings. A wired port
  shows no editor (the wire is the value); the slider's own `value`
  port belongs to its widget row; an expression's free variables are
  names, not literals. Observers and `#off` ghosts see the text — the
  literal, or the default greyed — and no chip. The chips follow the
  LOD table below (hidden at `mid` and `far`), and the same chip sits
  in the inspector's Node tab, opened by a single click (§Inspector
  contents). `web/src/canvas/LiteralChip.tsx`; the face rule in
  `literalFace.ts`, pinned by its test; `web/e2e/literals.spec.ts`.
- **Sliders** (wave 4 B4, findings U10 + U11, 2026-08-24). Two GH
  habits, native:
  - **The shortcut.** Typed into the bare search-to-place, `A<B` or
    `A<B<C` is not a node name but the slider to make — min `A`, max `B`
    (or `C`), value `A` (or `B`), negatives allowed, whitespace ignored;
    the step is the precision typed, `10^-(the most decimals typed)`, so
    `0.0<0.5<1.0` steps by 0.1 and whole numbers make GH's **integer
    slider**: step 1 on whole values (`1<20` → `slider(value=1.0,
    min=1.0, max=20.0, step=1.0)` — the `slider` node's ports are
    `Number`, so the literals are spelled as every Number literal the
    canvas writes; there is no Integer-typed slider node). The search's
    one row PREVIEWS it (`integer slider 1.0 … 20.0 · value 1.0 · step
    1.0`); Enter or a click places it as ONE op — a `place_node` carrying
    the four literals (`params`, docs/13) — so one `Ctrl+Z` removes the
    slider whole. `min` must be below `max` and `value` within them: else
    the row says why in the error colour (`min 5 must be below max 2`,
    `value 7 is outside 0 … 5`), Enter is a warning notice and nothing is
    placed. Not offered in the wire-dropped search (that search wires
    the new node, and the grammar names no port for the wire).
    `web/src/canvas/sliderShortcut.ts`, pinned by its test;
    `web/e2e/search.spec.ts`.
  - **Collapsed.** A slider collapses to **one grid unit** — its name,
    the same track and the value on one row, the output handle at the
    right edge; no header, no port rows — from the node's context menu
    (`collapse` / `expand`) and the inspector's actions. It is the
    sidecar's existing `collapsed` override, written by the
    `set_collapsed` intent as an op like a move (`collapse size`, undo
    walks it back; expanding clears the override, so an untouched sidecar
    stays empty). The SERVER decides who may, off the document (so a
    `batch` sees what it wired a moment before — docs/13): only a slider,
    and only while `value`, `min`, `max` and `step` are literals — the
    collapsed row is name · track · value · output, and a wire into any of
    the four has no port to reach (the track IS `value`) — so a wired port
    is refused with a notice (`bound: max is wired — a slider collapses
    only while value, min, max and step are literals`); the menu item and
    the inspector button mirror that reason as their hint beforehand —
    offered for every slider, widget or not — and a slider whose bound a
    text edit wires afterwards is drawn expanded until the wire goes (the
    flag stays). Collapsing changes the node's height, and the auto-layout
    packs by size: auto-placed neighbours re-pack on collapse / expand
    (manual cells never move) — GH never moves a neighbour; keeping the
    expanded slot for layout only is the tweak if the jump grates. A
    `#off` slider collapses like any other (a ghost keeps its moves and
    its collapse; it renders as a disabled one-row slider). The collapsed
    row wears the state badge only for a problem — red, blocked, off —
    the value says the rest, and `data-state` carries it always; the git
    badge stays. The far-tier LOD hides the widget as on every node,
    leaving the name.
    `CicadaNode.tsx` (`CollapsedSlider`), `collapse.ts` (the mirror),
    `collapsedSlider.test.tsx`; `web/e2e/slider.spec.ts`.
  - **Scrub-cached** (v0.1 item 5 S2, 2026-08-24; docs/12 §Speculative
    warming, docs/13 §Scrub caching). A slider whose text says
    `scrub=True` has its step positions pre-solved while the app is idle,
    and wears the **buffer bar** — video-player style — under its track
    on BOTH widgets (the canvas node, expanded or collapsed, and the
    params row): one segment per position, the warm ones filled in the
    accent, the notch the thumb is on ringed (it follows a drag's own
    value, the pending value of a compute-on-release drag, else the
    committed one), the cold ones pulsing softly while the server's
    worker still has work (`warming`; no motion under
    `prefers-reduced-motion`), and in the warn hue when the 256 MiB cap
    stopped it (`capped` — the warm positions stay). Everything the bar
    draws is the SERVER's: the slider's `param.scrub` from the last
    snapshot / delta with the coalesced `scrub_progress` broadcast laid
    over it — the client computes no eligibility and no warm set;
    observers see the same from the broadcast. The bar is absolutely
    positioned along the widget row's bottom edge on the canvas (the track
    never changes size under a held pointer, as with the pending chip) and
    a line under the range in the params row's track column; it hides
    with the widget at the far LOD tier. The tooltip reads `scrub cache ·
    7 / 19 positions warm · warming while the app is idle… · 1.97 MB
    stored`. **The toggle** — "scrub-cache this slider" / "stop
    scrub-caching" — is a switch (checked = the text's `scrub=True`) in
    the inspector's actions row, a compact `scrub` pill in the params
    row, and an item in the node context menu; each sends `set_scrub
    {node, on}` and the server edits the kwarg (one op, `scrub x on` /
    `scrub x off`, undoable). An ineligible slider's toggle is **greyed
    with the server's own reason** (`param.scrub.ineligible`, verbatim —
    `too many positions (51 > 32)`, `max is wired — the positions are a
    function of literal min, max and step`, `step is 0 — …`) while it is
    off — the same words `set_scrub` refuses with if the intent is
    forced; a slider that is ON and ineligible (a hand-written kwarg the
    server warms nothing for) keeps a live toggle, since turning it off is
    always allowed. Observers and `#off` ghosts see the state, disabled.
    Every surface of the toggle reads the same MERGED view as the bar —
    `param.scrub` with the `scrub_progress` overlay laid over it — so the
    menu item's hint (`7 / 19 positions warm`) and the switch's and the
    pill's tooltip (`7 / 19 positions warm — pre-solved while the app is
    idle …`, also `data-hint`) move with the broadcast, never a stale count
    under a full bar (the S2 review of 2026-08-24 found the menu reading the
    raw graph view: `0 / 19 positions warm` under 19 filled segments;
    `scrubToggle` now takes the overlay as a required argument).
    The `scrub` port row on the canvas node STAYS (docs/17 §Wave 4 —
    second half, S1 deviation 12, decided here): it is the kwarg itself,
    editable like every typed literal, the server sizes the node for it,
    and hiding the hand-written word on one surface while the inspector
    shows it would be a lie — the toggle and the bar are the designed
    affordances, the row is the text. The compute-on-release tie-in needs
    no client code (docs/13 §Slider drags): a tick on a warm position is a
    pure cache read and previews live; a cold tick that would compute ≥ 1 s
    is withheld and shows the pending chip.
    `web/src/canvas/ScrubBar.tsx` + `scrub.css` (the one bar),
    `web/src/panels/ScrubToggle.tsx`, `web/src/canvas/scrubMenu.ts` (the
    menu item, a pure builder `Canvas.tsx` spreads — pinned through the
    real `ContextMenu` by `scrubMenu.test.tsx`, greying included),
    `web/src/state/scrub.ts` (the merge,
    the current notch, the toggle's state — pure, pinned by
    `scrub.test.ts`), `store.scrubProgress` (the broadcast kept BESIDE the
    graph, merged on read, cleared by every snapshot / delta — writing it
    into the graph would rebuild the canvas and re-route every trace wire
    at the broadcast's 10 Hz); `ScrubBar.test.tsx`, `ScrubToggle.test.tsx`,
    the bar cases in `ParamWidget.test.tsx` / `ParamsPanel.test.tsx`;
    `web/e2e/scrub.spec.ts` (02-solids warm and toggled; a Python-burn
    pipeline for the live-vs-withheld tie-in, the observer's bar, the
    greyed `fine`).
- **Wires**: depth-styled per doc 09 (single / double / hatched +
  number); kind-colored; red on error. During a wire drag,
  incompatible ports dim with a hover reason, liftable ports show
  the chip (doc 09's blocked-wires contract).
- **Wire display modes** (settings toggle): **spline** — the
  GH-traditional bezier look, default — or **trace** — orthogonal
  routing in 45° increments, PCB-style, on a ¼-grid-unit lane lattice
  anchored on the port rows.
  Both modes carry the same depth styling, kind colors, stroke widths
  and chips; the choice is a per-user app setting, never file state.
  *The trace router (wave 4 B2, finding U6, 2026-08-24) is our own —
  `web/src/canvas/trace.ts`, pure, pinned by `trace.test.ts`; React
  Flow's smooth-step path is gone from trace mode:*
  - **Runs and corners.** A wire leaves its output rightwards and enters
    its input from the left; its runs are horizontal and vertical, and
    every 90° turn is cut at 45° — the PCB mitre — with legs of
    **`TRACE_CORNER_UNITS` = 1 grid unit** (the corner's "radius").
    Three routes: a target to the right within **`TRACE_STAIRCASE_UNITS`
    = 6 units** is the **Z** (stub · cut · vertical channel halfway
    between the nodes · cut · stub; a jog shorter than two legs is one
    45° diagonal; a level target is a line); a target further right is
    the **stair** — an escape of `TRACE_ESCAPE_UNITS` = ½ unit plus a leg
    beside each node and the long run in a horizontal channel between
    the two rows, so a long run is never a stub pinned along a row of
    nodes (when every channel between and on its rows is taken it
    detours a full leg or more beyond them; a level target is a line
    unless its row is taken); a target to the left is the **back route** —
    out, down beside the source, a channel leftwards, up beside the
    target, in — with the channel halfway between the rows when six
    legs fit there, else three legs below both: a U-turn's two cuts have
    the same sense and would meet at 90° on a two-leg run, so every run
    of a U-turn is at least three legs (the Z's and the stair's pairs
    have opposite senses and merge into one diagonal).
  - **Lanes.** Every run occupies its line on a **`TRACE_LANE_UNITS` =
    ¼-unit lattice** over its extent — the horizontal lattice anchored
    on the port rows (their residue modulo the pitch, so a row and a leg
    off it are lines of it), the vertical one the grid's. The stubs out
    of and into a port are pinned to the port's row (a wire must reach
    its handle) and are recorded first; the horizontal channels — the
    stair's, the back route's — are then placed in one order (source
    position, target position, then the wire id), each on the row line
    nearest its natural place that no other wire's run occupies; then
    the vertical runs — the Z's channel, the stair's and the back
    route's escapes — are solved a COLUMN at a time (the runs that can
    meet: overlapping extents, or stubs on a shared row that can run
    into each other) by a depth-first search in top-down order over each
    run's lines, nearest its natural place first, under two constraints:
    no two overlapping runs on one line, and no stub — at the length its
    line gives it, as drawn — running into another wire's run on its row
    (a channel, a level line, or the stub of a port that shares the row;
    wires out of ONE port share their stub until they part — a trunk, as
    on a board). The natural-first greedy is the search's first branch;
    it backtracks only where that fails — the wall's busiest three-unit
    gap carries 22 vertical runs, 8 deep, on seven lines a Z may take,
    and a stair's vertical steps out to a line a Z cannot use. All of it
    once per canvas render over EVERY wire (a memo over the graph and
    the live node positions, `traceLanes.ts`; the edges read theirs from
    a context), pure in its inputs, so a re-render moves nothing. Where
    a gap is too narrow for full legs AND the lanes (the auto-layout's
    adjacent layers are two units apart), the legs shrink toward
    **`TRACE_MIN_LEG_UNITS` = ½ unit** before any two runs are let
    coincide — finding U6 ranks the two rules: the radius "~1 unit", the
    overlap "never". Only a column with no overlap-free assignment at
    all (within `LANE_SEARCH_BUDGET` placements) falls back to the
    greedy — the nearest free line, else the line with the fewest runs
    over the extent, so coincidences spread rather than stack — and the
    router MEASURES its own drawing: every wire whose run coincides with
    another's is in `TraceLanes.collapsed`, shown as the canvas's
    `data-trace-collapsed` count (0 on every committed example, the wall
    included — `web/e2e/traces.spec.ts`, `wall_traces.spec.ts`), and an
    edge that drew its natural route because the assigned one disagreed
    with its measured handles marks itself `data-trace-yield`; neither
    fallback is silent. The router knows no obstacles: a run may cross a
    node in its way, as the spline does — a channel along a row a node
    sits on crosses its face; obstacle-aware channels are the next
    finding to take (docs/17 §Follow-ups). The in-flight connection line
    takes the same path, unlaned. The model's endpoints carry the handle
    geometry React Flow measured (overhang, row shift), so lanes are
    assigned on the endpoints the edges are drawn from; the sliders'
    output handles sit a pixel below the other nodes' rows, which the
    one measurement does not see — a kink of a pixel on their wires at
    most.
- **Zoom LOD**, four tiers (GH's zoom-UI plus the Sunglasses plugin,
  native), by the canvas zoom factor (`web/src/canvas/grid.ts`
  `lodTier`, pinned by `grid.test.ts`):

  | Tier | Zoom | Shows |
  |---|---|---|
  | far | < 0.35 | icon-only boxes (name large; the git marker as a stripe) |
  | mid | 0.35 – 0.65 | ports visible (handles, badges); no labels, no literals |
  | near | 0.65 – 1.6 | port labels, inline literals, **and the output value summaries** — every output shows what is sitting on it: scalar values, list counts with first samples |
  | closest | ≥ 1.6 | the same; reserved for the tiny geometry thumbnails and the deeper inline widgets when they land |

  *Revised 2026-08-24 (wave 4 B1, finding U7 — "port value previews need
  too much zoom"): the summaries appear one tier earlier than the
  original design's `closest`; one rule (`showsPortValues`) gates both
  the node face that renders them and the canvas that fetches them.*
  Previews are fed from the same cached wire summaries the inspector
  uses (an `inspect` per visible solved node when the tier shows
  values); thumbnails are content-addressed (value hash → sprite,
  rendered lazily), so the feature costs nothing when idle and never
  renders the same value twice. Deeper inline *editing* widgets remain
  an open question.
- **Search-to-place**: double-click canvas (or `Ctrl+F`) opens a
  search box over the catalog — start typing the node you want. v1
  is plain prefix/substring matching, run over the dialect name, the
  title AND the Grasshopper component the node replaces (`gh`, doc 14
  §node file format — a migrant types `Merge` and lands on `concat`),
  ranked exact > prefix > substring (among exact hits: name, then
  `gh`, then title — `Round` gives `round` before `ceiling`/`floor`,
  whose GH component is also Round); a row shows `GH <name>` when the
  GH name differs from the title by more than case, so the user sees
  why the node answered. Fuzzy matching comes later. GH's slider
  shortcut — `1<20`, `0.0<0.5<1.0` — is understood in the bare search
  (§Sliders above). **Dragging a wire
  onto empty canvas opens the same search filtered to compatible
  ports** — the single best GH gesture, kept.
- **Selection**: click, shift-click add, marquee, `Ctrl+A`; selection
  syncs both ways with the viewport (backward picking highlights the
  producing node; canvas selection highlights its geometry).
- **Disable/enable** (GH's most-used toggle, native): a disabled node
  ghosts on canvas with wiring intact and is skipped in solves;
  downstream reds with "fed by disabled node" as the reason. The text
  form is the `#off` prefix (doc 10); re-enabling is usually a pure
  cache hit, so the red interlude costs nothing.
- **Groups, first-class and purely visual** (sidecar state): create
  from selection, title + color, collapse to a single tile — pure
  rendering, members persist, outside wires draw to the tile — plus
  batch move/select/disable. Promoting a group to real semantics is
  `extract_script` (doc 11), a deliberate act; visual tidiness never
  changes meaning.
- **Context menus**: node (toggle preview, collapse/expand on a slider
  — the hint mirrors the server's refusal for a wired bound, §Sliders —
  scrub-cache this slider / stop scrub-caching on a slider — greyed with
  the server's reason when it cannot, §Sliders §Scrub-cached —
  disable/enable, isolate, rename, show in text, history), wire
  (inspect, insert node here), canvas (search, paste, group selection).

## Icons

Every stdlib node has a small icon (GH-style — a graph is parsed at a
glance by shape and color, not by reading):

- Generated by an **AI icon pipeline**: NodeSpec (name, title,
  category, description) → image model → post-processed to consistent
  size, stroke weight, and per-category accent hue. Committed as
  generated assets, referenced from the JSON catalog; CI warns on any
  node without one.
- Small and theme-aware (SVG preferred); the category hue matches the
  ribbon tab and the port color family, so tab, ports, and icon all
  agree.
- Script nodes get an auto-glyph fallback (initials on the category
  hue); authors may supply a custom icon, and the pipeline can
  generate one from the node's doc comment on request.
- The spike ships with fallback glyphs; the generated set lands with
  the v0.1 catalog.

## Viewport conventions

- **Navigation: Rhino-style by default** (RMB orbit, Shift+RMB pan,
  wheel zoom-to-cursor) — the muscle memory of the target migrant —
  with a Blender preset and remapping available.
- Ground grid + axes gizmo; display modes: shaded+edges (default),
  shaded, wireframe, ghosted. Per-node preview toggles (doc 02);
  display cost visible in the profiler (doc 04).
  - The **ground grid** lies in XY (Z up), sized to the scene, on the
    `--grid-strong` / `--border-strong` tokens; the origin triad is
    drawn at two grid steps.
  - **Axis colours: X red, Y green, Z blue** — the `--axis-x` /
    `--axis-y` / `--axis-z` tokens (per theme: the light theme's are
    darker so they read on a light ground). This is the CAD convention
    the target migrant knows from Rhino and Blender and the one hue set
    in the app that is not semantic (§Theme). The origin triad and the
    gimbal share them.
  - The **gimbal** (since 2026-08-24, wave 4 B1, finding U5): a small
    X/Y/Z triad — three bars with lettered discs at their tips — in the
    viewport's upper-left, under the toolbar overlay, 72 px square
    (`web/src/viewport/gimbal.ts`). It is a second tiny scene the same
    renderer draws into a corner viewport at the end of every main
    render, its orthographic camera on the main camera's bearing, so it
    follows the camera each frame and — the scene renders on demand —
    costs nothing while the view is still. Non-interactive in this
    slice: click-to-snap (look along an axis) is deferred. It is part of
    the WebGL canvas, so `/debug/screenshot` and `window.__cicada.
    screenshot()` include it, and `window.__cicada.scene().gimbal`
    reports each world axis as the GIMBAL's own camera sees it
    (`Gimbal.directions()`; `[right, up, toward the viewer]`) for tests
    — what is drawn, never the main camera's pose, so a triad that
    stopped following reads as frozen (review finding 2026-08-24; the
    e2e spec also asserts the drawn red pixels' centroid moves on an
    orbit).
- **Backward picking is the flagship gesture** (doc 04): click
  geometry → node + `parts[412]` + part ID light up, inspector shows
  the element. Hover = lightweight highlight; click = select.
- Camera bookmarks (named, saved in sidecar views; feed the Blender
  bridge's cameras, doc 04).
- **The pop-out** (shipped 2026-08-24, v0.1 wave 4 O3 — docs/17 finding
  U8): the viewport toolbar's **pop out** button opens `window.open(<this
  page> + "&view=viewport", "cicada-viewport")` — a second window for a
  second monitor (the fixed name means a second click focuses the
  existing window — and, as `window.open` re-targets a named window,
  navigates it to the main window's CURRENT pipeline, so a pop-out left
  on a closed file follows when asked). With `view=viewport` the SPA renders the **viewport
  alone** — no canvas, ribbon, panels, top bar or hotkeys; a chip names
  the pipeline and `read-only observer`; the connection banner and the
  notices are the app's — and its socket joins as a **declared
  observer** (docs/13 §Projects, pipelines, sessions — the join hint
  `role: observer`): it never takes the writer lease, not at its join,
  not when the main window's socket drops and reconnects, not by
  `take_lease` (refused with the reason), so the second window can never
  steal the first one's lease. Same pipeline, same display set live —
  the main window's writes move its geometry — and its **own camera**:
  camera sync between the windows is explicitly not in this slice. It
  shows no pop-out button of its own, and it stays on the pipeline it
  was opened for (the main window switching files does not move it).
  `web/e2e/popout.spec.ts` is the evidence.
- Partial results stream in as elements complete; a cancelled solve
  leaves the last coherent frame (docs 04/12/13).

## Inspector contents

- **Node selected**: ports with current values — an unwired
  literal-typed port wears the same typed-literal chip as the canvas
  (§Canvas conventions), opened here by a **click**; Enter commits,
  Esc cancels; a wired port names its source (click → select it);
  observers read the literal or the default — status + warnings with
  element IDs, compute + display timings, contract results, prompt
  provenance for AI-authored nodes, "show in text"; the actions row
  carries **collapse / expand** for a slider (§Canvas conventions
  §Sliders), its title mirroring the server's refusal for a wired bound,
  and the **scrub-cache toggle** for a slider (§Sliders §Scrub-cached;
  item 5 S2) — checked when the text says `scrub=True`, greyed with the
  server's reason when the slider cannot scrub-cache; the params row
  carries the same toggle compact.
- **Wire tapped** (doc 02's flagship inspection): type, counts,
  bounds, sample values, pairing readout (what mapped/zipped over
  what — doc 09), small geometry preview.
- **Nothing selected**: pipeline overview — diagnostics list (click
  → node), solve summary, cache stats.
- **Git tab** (2026-08-20, slice 1 — see the Git panel bullet above):
  repository state · nodes vs HEAD (click → node) · files to commit ·
  commit form · revert-to-HEAD with confirm; the tab label wears the
  dirty-file count.

## Status and progress language

One vocabulary everywhere (canvas badges, status bar, inspector):
`cached · queued · running (progress) · done (time) · red (error) ·
blocked · cancelled` — exactly the scheduler states of doc 12 — plus
`idle` for a node no generation has touched yet (a fresh pipeline's
first frame, or an exporter that runs only on explicit action; revised
2026-08-19 with the stage-5 implementation). The
global solve bar shows cost-weighted progress + ETA and the Esc hint;
per-node progress bars appear on >1 s nodes (doc 12).

## Settings

Per-user app settings, never project state: theme, viewport
navigation preset, wire display mode (spline / trace), keybindings,
layout preset. Project-affecting configuration (units, tolerance)
lives in `ProjectConfig` (doc 14) — the settings menu never silently
edits project semantics.

## Theme and visual language

Dark-first, light available. Color is semantic and reserved: red =
error, amber = warning/stale, accent = selection, kind hues for
ports/wires only (and the viewport's axis triad — X red, Y green, Z
blue — the one conventional, non-semantic hue set; §Viewport
conventions). GH familiarity is kept wherever it costs nothing
(wire depth styling, search gestures, slider feel); density leans
professional tool, not consumer app.

The tokens live in `web/src/styles.css` (`:root` = dark;
`[data-theme="light"]` overrides). Two are recorded here because a user
test set them (2026-08-24, finding U4 — "grid lines ~50 % less visible,
closer to the background"): the **grid tokens sit halfway between their
previous values and `--bg`**, per channel —

| Token | Dark | Light | Used by |
|---|---|---|---|
| `--grid` | `#1b1e23` (was `#20242a`; `--bg` `#15171b`) | `#eef0f4` (was `#e8ebf0`; `--bg` `#f4f5f7`) | the canvas's grid lines |
| `--grid-strong` | `#202329` (was `#2a2f37`) | `#e9ebf0` (was `#dde1e8`) | the canvas's dot variant; the viewport's ground grid (its major lines are `--border-strong`) |

`web/src/viewport/theme.test.ts` holds the stylesheet to these values
and to the halfway rule, and the viewport's fallback table
(`theme.ts`) to the stylesheet.
